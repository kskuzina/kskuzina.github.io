# CLAUDE.md

Локальная инструкция для работы с сайтом `kskuzina.github.io`.

Этот проект — статический сайт Ксении Кузиной: профессиональная страница психолога, условия работы, образование, материалы, информированное согласие и полезные ресурсы.

---

## Быстрый старт

Перед любыми изменениями:

1. Выполни `git status --short`.
2. Прочитай этот файл.
3. Открой только нужные HTML/CSS-файлы в `docs/`.
4. Если задача связана с текстом из Notion, сначала найди релевантный файл в `notion_export/` или `all_exports/`, но не считай экспорт автоматически более актуальным, чем `docs/`.

Обычный безопасный набор команд:

```bash
git status --short
git log --oneline -5
rg --files docs
rg -n "текст|href|class" docs
python3 -m http.server 8000 --directory docs
```

`python3 -m http.server 8000 --directory docs` нужен только для локальной проверки сайта в браузере. Build-команды нет: сайт статический.

Не выполняй и не печатай `git remote -v` без необходимости: remote URL в этом проекте может содержать приватный credential.

## Source of truth

### Живой сайт

`docs/*.html` и `docs/css/style.css` — фактический опубликованный сайт.

Если задача звучит как “поменять сайт”, работай в `docs/`.

### Notion exports

`notion_export/` и `all_exports/` — архивы и reference. Они полезны, когда нужно сверить формулировку или перенести материал, но не являются автоматическим source of truth.

Правило:

- Если Ксения явно говорит, что актуальный текст в Notion/export, перенеси его вручную и аккуратно в `docs/`.
- Если такого указания нет, считай `docs/` текущей опубликованной версией.
- Не перезатирай HTML целиком экспортом из Notion.
- Не удаляй старые exports/zip без отдельного согласия.

## Правила HTML

Проект без шаблонизатора: навигация, mobile menu, footer и небольшой JS-блок повторяются в каждом HTML-файле.

Если меняешь nav/footer:

1. Обнови desktop nav во всех `docs/*.html`.
2. Обнови mobile menu во всех `docs/*.html`.
3. Обнови footer во всех `docs/*.html`.
4. На текущей странице поставь `class="active"` в desktop nav и mobile menu.
5. Проверь, что ссылки относительные и работают из `docs/`.

Текущие страницы:

- `index.html`
- `about.html`
- `help.html`
- `how-it-works.html`
- `education.html`
- `materials.html`
- `consent.html`
- `ethics.html`
- `resources.html`

Для новой страницы:

- скопируй структуру ближайшей существующей страницы;
- подключи `css/style.css`;
- добавь `lang="ru"`, `meta viewport`, корректный `<title>`;
- добавь страницу в nav/mobile/footer, если она должна быть публичной;
- проверь mobile layout.

## Дизайн-система

Сайт держится на общей эстетике:

- мягкий тёплый фон;
- glass-карточки;
- большие скругления;
- шрифты `Unbounded` для заголовков и `Inter` для текста;
- фиксированная верхняя навигация;
- `blobs`/grain/vignette как общий фон;
- CTA через Telegram.

Основные классы:

- `.container`, `.container-wide`
- `.page`, `.page-hero`
- `.glass`, `.glass-lg`, `.glass-dark`, `.glass-warm`
- `.btn`, `.btn-dark`, `.btn-outline`, `.btn-accent`
- `.nav`, `.nav-links`, `.mobile-menu`, `.burger`
- `.contacts-block`, `.steps`, `.education-block`, `.about-grid`

Не делай отдельный визуальный язык для одной страницы без причины. Новые блоки лучше собирать из существующих классов.

## Контентный стандарт

Это публичный сайт практикующего психолога. Формулировки должны быть точными, спокойными и профессиональными.

Нельзя выдумывать:

- образование, сертификаты, годы и организации;
- цену, условия оплаты, формат сессий;
- наличие мест, льгот, расписание;
- терапевтические гарантии;
- диагнозы и обещания “вылечить”.

Особо осторожно:

- `consent.html` — информированное согласие, условия работы и границы ответственности.
- `ethics.html` — этический кодекс и ссылки на документы.
- `how-it-works.html` — цена, формат, отмены, анкета.
- `education.html` — образование, сертификаты, конференции.

Если задача касается этих страниц, меняй только то, что прямо попросила Ксения, или явно помечай, где нужна её проверка.

## Проверка

Для текстовой правки:

```bash
git diff -- docs
rg -n "старый текст|новый текст" docs
```

Для структурной правки:

```bash
python3 -m http.server 8000 --directory docs
```

Потом проверить в браузере:

- desktop ширина;
- mobile ширина;
- nav/mobile menu;
- footer;
- внешние CTA;
- изображения и документы;
- отсутствие горизонтального скролла.

Если менялись ссылки:

```bash
rg -n 'href="' docs/*.html
```

## Деплой и git

Сайт подготовлен под GitHub Pages из папки `docs/` на ветке `main`.

После логически завершённой правки:

1. `git diff --check`
2. `git status --short`
3. Коммит с коротким сообщением по смыслу.

Не делать:

- force push;
- reset/rebase без явной просьбы;
- массовую переформатировку всех HTML;
- замену всего сайта с нуля, если задача точечная.

## Известные технические долги

- Нет шаблонизатора: nav/footer/menu/JS дублируются в каждом HTML.
- Много inline-style в HTML.
- Внешние ссылки с `target="_blank"` в основном без `rel="noopener"`.
- Нет автоматической проверки ссылок и HTML-validity.
- Нет README для пользователя, только этот агентный протокол.
- Notion exports не имеют явного признака “актуальный/устаревший”.

Агент в этом проекте — аккуратный редактор и frontend-помощник для статического сайта.
